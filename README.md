# 計画と実行 — 1日のタイムスケジュール

1日の「計画」と「実行（実績）」を並べて記録する、iPhone向けのWebアプリ（PWA）です。

## 主な機能

| 場所 | できること |
|---|---|
| タイムライン | 空き場所を2回タップしてブロック作成／ブロックをタップして編集・削除 |
| 下部ボタン | 「今から開始」で実行を記録、「次を開始」で前の記録を自動で終了 |
| ヘッダー「📊 集計」 | 表示中の日のカテゴリ別「計画」「実行」「差」 |
| ヘッダー「⚙ 設定」 | 前日の計画をコピー／この日のCSV書き出し／カテゴリの追加・編集／バックアップの書き出し・読み込み／バージョン表示 |

- カテゴリを削除しても、記録済みのブロックは元の名前・色のまま残ります（設定の「削除したカテゴリ」から元に戻せます）。
- iPhoneでファイルを書き出すと共有メニューが開きます。「"ファイル"に保存」を選ぶと、ファイルアプリに保存されます。
- 機種変更やデータ消失に備えて、ときどき「バックアップを書き出し」をしておくと安心です。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み・iPhone向け設定 |
| `style.css` | デザイン |
| `app.js` | アプリ本体 |
| `sw.js` | オフライン対応・更新の仕組み（Service Worker） |
| `manifest.json` | ホーム画面に追加したときの名前・アイコンなど |
| `icons/` | アプリアイコン |
| `dev-server.js` | PCで動作確認するためのサーバー（公開には不要） |

## GitHub Pages で公開する手順（初めての方向け）

コマンドは使わず、ブラウザだけで公開できます。

### 1. GitHub のアカウントを作る
1. <https://github.com> を開き、「Sign up」から無料アカウントを作ります。
2. ここで決める **ユーザー名** が、公開URLの一部になります。

### 2. 置き場所（リポジトリ）を作る
1. ログインしたら、右上の「＋」→「New repository」を押します。
2. **Repository name** に `timeschedule` と入力します（半角英数字。別の名前でも構いません）。
3. **Public** を選びます（無料プランで GitHub Pages を使うには Public が必要です）。
   - 公開されるのはアプリの画面だけです。記録したデータはiPhoneの中にだけ保存され、GitHub には送られません。
4. そのほかは初期設定のまま、「Create repository」を押します。

### 3. ファイルをアップロードする
1. 作成直後の画面で「**uploading an existing file**」というリンクを押します。
2. PCで `timeschedule` フォルダを開き、**中身をすべて選択**して、ブラウザの枠にドラッグ＆ドロップします。
   - `index.html` `style.css` `app.js` `sw.js` `manifest.json` と `icons` フォルダが必要です。
   - ⚠ `timeschedule` フォルダごとではなく、**フォルダの中身**を入れてください。フォルダごと入れると、URLがずれて表示されません。
3. 一覧に `icons/icon-180.png` などが表示されていることを確認します。
4. 下の「**Commit changes**」を押します。

### 4. GitHub Pages を有効にする
1. リポジトリの上部にある「**Settings**」を押します。
2. 左のメニューから「**Pages**」を選びます。
3. 「Build and deployment」の **Source** で「Deploy from a branch」を選びます。
4. **Branch** で `main`、その右で `/ (root)` を選んで「Save」を押します。
5. 1〜3分ほど待ってからページを再読み込みすると、上部に
   `Your site is live at https://ユーザー名.github.io/timeschedule/`
   と表示されます。これが公開URLです。

### 5. iPhone のホーム画面に追加する
1. iPhone の **Safari** で公開URLを開きます（Chromeなど他のブラウザでは追加できません）。
2. 画面下の **共有ボタン**（四角から上向き矢印が出ているアイコン）を押します。
3. メニューを下にスクロールして「**ホーム画面に追加**」を押します。
4. 名前が「計画と実行」になっていることを確認し、右上の「**追加**」を押します。
5. ホーム画面のアイコンから起動すると、アドレスバーのない全画面のアプリとして開きます。

> 💡 **注意**：iPhoneでは、Safariで開いたときと、ホーム画面のアイコンから開いたときとで**データが別々に保存されます**。
> 記録は必ずホーム画面のアイコンから行ってください。

## アプリを更新するとき

1. PCでファイルを修正します。
2. **`sw.js` の11行目にある `VERSION` の数字を1つ上げます**（例：`'v1'` → `'v2'`）。
   これを忘れると、iPhoneに古い画面が残ることがあります。
3. GitHub のリポジトリで「Add file」→「Upload files」を押し、変更したファイルをドラッグ＆ドロップして「Commit changes」を押します（同じ名前のファイルは上書きされます）。
4. GitHub で反映を確認します：リポジトリの「**Actions**」タブを開き、一番上の「pages build and deployment」に緑のチェック ✅ が付けば反映完了です（1〜3分）。
5. iPhoneでアプリを開きます。新しい版が自動で入り、画面が一度読み込み直されます。
6. **「⚙ 設定」を開き、一番下の「バージョン：v◯」が `sw.js` の `VERSION` と同じになっていれば成功**です。
   - 古い番号のままなら、アプリを上にスワイプして一度終了し、もう一度開いてから確認してください。

記録したデータは、更新しても消えません。

## 動作確認の方法

### PCのブラウザで確認する
1. `timeschedule` フォルダで、次のコマンドを実行します（Node.js が必要です）。
   ```
   node dev-server.js
   ```
2. Chrome または Edge で <http://localhost:8080> を開きます。
3. **F12** キーで開発者ツールを開き、**Ctrl + Shift + M** を押して表示サイズを「iPhone」に切り替えると、iPhoneに近い見た目で確認できます。
4. 止めるときは、コマンドを実行した画面で **Ctrl + C** を押します。

※ `index.html` をダブルクリックして開いても画面は動きますが、オフライン機能（Service Worker）は動きません。

### iPhoneで確認する
Service Worker は https のページでしか動かないため、iPhoneでの確認は GitHub Pages に公開してから行います（上の手順5）。

確認ポイント：
- 今日を開くと、現在時刻（赤い線）のあたりまで自動でスクロールされる
- 空いている所をタップ → もう一度タップ → 内容とカテゴリを入力してブロックができる
- 縦にスクロールしても、ブロック作成の操作が始まらない
- ブロックをタップすると編集・削除ができる
- 「今から開始」→ カテゴリ選択で記録が始まり、「次を開始」で前の記録が自動で終了する
- 機内モードにしてもアプリが開ける（オフライン動作）
- 画面上部の時計や下部のホームバーにボタンが重ならない
